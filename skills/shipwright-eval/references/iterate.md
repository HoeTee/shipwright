# Iterate

一次只改 skill 的一处。用版本对比跑相关题。越过噪声，并且隐藏检查不退步，才保留；否则整处回退。不把没测过的改动叠上去。不从读代码宣布赢了。原则 [prove-it-works](../../../references/principles/prove-it-works.md) 见 [共享原则目录](../../../references/principles/README.md)。

这是对一个可测量目标的持续迭代。一次性修复走别的 skill。指标和实验的完整性由本 skill 负责。尝试可以派独立执行者去做，主控监督并看 diff。

## Loop

1. 先写下希望能说的那句话、什么算更好，以及停止条件。停止条件把目标和最少尝试次数放在一起，例如「误报率降一半，并且至少试 8 次」，避免一次运气好就收工。用用户给的数字；没有就先约定。中途不放宽。
2. 把题库和隐藏检查冻结成量具。先用一好一坏的样例证明它分得开，再冻结。冻结前用 [numbers.md](numbers.md) 的七问检查。冻结后一条命令打出指标、错误数和实际完成的工作数。采样要够越过噪声：取 N 次的中位数，不取单次。改 skill 之前，记下基线，并确认回归门是绿的。
3. 打开 `decision.tsv`，放在 git 外，例如 `/tmp/shipwright-eval-<plan-id>/decision.tsv`。每次尝试一行：`id`、`hypothesis`、`change`、`before`、`after`、`delta`、`tests`、`verdict`（`kept` 或 `reverted`）、`note`。每次尝试前先读它。
4. 每条假设点名一个机制，例如「评委把风格建议当成阻断，所以把阻断的定义收成有用户可观察的后果」。性能指标的假设顺序用 shipwright-perf 的口诀，只借顺序，不借它的停止规则。skill 的假设按这次要压低的真实漏检或误报来排。
5. 一轮一条假设：
   - 把这一处改动交给独立执行者，范围写紧。主控看 diff。几条互不相关的假设可以同时派，各自一个工作区。
   - 用冻结的量具量改前和改后，并跑回归门。
   - 只有指标越过噪声且隐藏检查不退步才保留。否则整处回退。「也许有用」的小改动不留。
   - 接受的修正一次一个 commit，只暂存改过的文件，不用把整个工作区都加进去。保留或回退都写一行日志。
   - 这一轮的检查结束，再开始下一轮。
6. 越过第一个平台。连续几次被拒时，换一类假设，把接近的失败合起来看，重读 skill，或试更彻底的一处，然后再说已经到顶。正确和简单优先于数字。破坏行为的「赢」要回退。保住数字的简化可以留。
7. 停止条件达到时停。剩下的主意收益已经配不上代价时也可以停。便宜又还没试的假设还在时，不停。卡住了就说出来。
8. 接受的 commit 按落地顺序交给 shipwright-ship。发布前做下面的三组确认。

## What a skill change may use as evidence

规则改了，只重跑相关场景。只根据真实漏检或误报把规则改窄。不为了凑分去改题、改评委或改隐藏测试。

程序回归和审查效果分开统计。插件脚本或渲染器坏了，不写成「审查变准了」或「审查变差了」。

## Several edits at once

几种改法同时比时，用 shipwright-arena 的 fan-out 和异族评委。arena 的正文由那个 skill 维护。评测要跑的部分是：

- 每组同一句任务。评分表 3 到 6 条，只给评委和主控。
- 在同一条消息里派全部组，各自一个目录，互不看见。目录名像项目，不用禁用词。某组没有产出，用其余组继续，并记下缺席。
- 各组都完成后，派一个只读评委，来自另一模型家族。评委按标签打分并推荐一个底稿。候选还在写时不派。
- 主控读完每一份输出再选。和评委不一致时，先读两边的理由：有人有偏，或评分表含糊。
- 选最容易继续维护、又不打破不变量的那一版当底稿。从其他版本只取一两处长处，手工合进去，让结果仍是一个连贯的做法。各组收敛成同一个形状时，采用这个形状。各组完全发散时，是题目没写清，重写题目再跑，不要把发散平均掉。
- 合成结果照常验证。验证发现 arena 没看见的问题，就回到题目或回到合成，不在报告里把它盖住。

## Final three-arm check

发布前用全量题库，在一次评测里同时跑三组：新版、上一版、不装 skill。同一模型，交替跑，每组至少 5 次。这一次的判定才用来决定发不发布。只跑过相关子集的迭代结果，不能代替这次确认。

## One-line control

怀疑整套 skill 只是一句短提示的分量时，加一组一句话对照。对照组的提示只有一句，写进计划。实验组是整套 skill。隐藏检查、完整度和注入 bug 的抓住率一起看。行数下降而安全或测试强度下降，不算赢。

## Reply

回复里写：指标和目标、基线到最终的差值、跑了几轮（保留几轮、回退几轮）、每处保留的修正一行、`decision.tsv` 的路径，以及如果还要继续、下一条最值得试的假设。

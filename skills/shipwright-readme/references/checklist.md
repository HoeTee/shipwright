# Pre-PR checklist

开 PR 前逐条核对。有一条做不到，就改 README 或删掉那句。规则正文在 `../SKILL.md`。两边冲突时以 `SKILL.md` 为准。

## Truth

- [ ] 每条说法对得上一个仓库文件，或这次测到的结果。
- [ ] 每个声称支持的平台都试过安装，或者已经删掉这句话。
- [ ] 没有编造的 manifest。缺的文件已经补上，或对应说法已删除。
- [ ] 没有 pending，没有占位。

## Layout

- [ ] 顺序是 Header、Hero、Workflow、核心表、Anatomy、Quick start、Evidence、FAQ、Philosophy、对照、许可证。
- [ ] Header 居中。方图 logo 在大标题旁。一句口号。徽章是 flat-square。
- [ ] Hero 宽而矮。关键数字大。文字垂直居中。空少。手机上能读。
- [ ] Workflow 是横向卡片。挤不下就两行。每个阶段一次。回路是 `Review ⇄ Fix`。GIF 若有，旁边有静态 PNG。
- [ ] 核心表三列：在做什么、命令或 skill、核心原则。标题用 README 的语言。不是 `main path`。
- [ ] Anatomy 在代码块里。有一份单元的方框，也有带数量的真实树。每一行对得上文件。行窄。
- [ ] Quick start 先写最快的一条安装命令。其他平台各自一节，写全。
- [ ] 没有 `<details>`。没有 mermaid。没有 `Repository guide`。
- [ ] 证据节不叫 `Numbers`。
- [ ] FAQ 是 `- **Question?** answer` 列表。问题和回答在同一条。没有每题标题，没有折叠。
- [ ] Philosophy 是 3 到 5 个主题。粗体标题加几句口语。没有出处。
- [ ] 对照表里本项目在最后一行。不能公平对照时改成 `Built on`，一行一个项目。
- [ ] 许可证一行。MIT 仓库写成 `MIT © owner/repo`，名字用这个仓库的。

## Evidence

- [ ] 数字都来自这个仓库的实测。没有用别的项目的数字。
- [ ] README 里只有少数关键数字，和一两张主图。方法和逐项细节在链接的报告里。
- [ ] 图上有一个大数字，和一行说明测的是什么。
- [ ] 可以再放一张交付了测试的图，以及一个标明「一个例子」的改前改后。没有数据就不放。
- [ ] 样本量不够的统计已删。难懂的原始分数改成一句实话，或删掉。

## Images

- [ ] PNG 由 HTML 经无头 Chromium 渲染。HTML 源文件在图片旁边。
- [ ] GIF 由 ffmpeg 生成。
- [ ] 全部图片同一套配色。字大，空少。alt 写了图中的数字。

## Writing

- [ ] 除 Philosophy 外，句子短、字面。
- [ ] 每种译文是那种语言写的。结构和图与原文相同。路径、命令、文件名仍是英文。
- [ ] 没有宣传句和填充句。

## Deliver

- [ ] 这一轮反馈只有一个 PR。
- [ ] PR 描述列出改动、数字和每个数字的来源文件。图片作为产物附上。
- [ ] CI 绿了才由所有者合并。本轮不合并。
- [ ] 合并之后另查图片和链接是否渲染。这一条不在开 PR 前勾。

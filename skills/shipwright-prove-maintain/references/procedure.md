# Maintain a formal verification skill

形式化检查证明的是它所描述的那个东西的属性。代码变了、验证没变时，检查可以继续通过，而它描述的代码已经不存在。这种通过是危险的，因为它看起来像证明。本 skill 维护的是 shipwright-prove-create 生成的验证 skill，或任何对着具名代码运行模型检验器、证明器或代码级验证器的项目 skill。项目 skill 自己处理「agent 正用着它时做的改动」。本 skill 处理绕过了它的改动：合并、没用这个 skill 做的编辑，以及许多 commit 累积下来的漂移。

## Outcomes

每个检查给一个结果，并写明是哪一个：

- **in sync**：上次同步之后，没有任何改动改变检查所描述的东西，并且检查通过。
- **updated**：代码变了，验证现在描述的是新代码，并且检查通过。
- **bug**：验证描述的是当前代码，而代码打破了属性。这是关于代码的发现，不是漂移。
- **blocked**：检查没能重新对上，或跑不起来。写明原因。

一个检查可以同时是 updated 和 bug：更新让验证重新描述代码，然后属性在这份代码上失败。

## Edit scope

只改验证：模型、测试工具、属性文件，以及验证 skill 本身。这一轮不改产品代码，除非用户要求。属性在当前代码上失败时，不要把属性或模型改弱来让它通过。报告这次失败。

验证的更新放在自己的改动里，和任何产品修复分开。

## Pass

1. **Find the checks.** 验证 skill 没有固定名字。按它做什么来找：一个项目 skill，对着具名代码运行模型检验器、证明器或其他验证器。读用户点名的那一个，或找到的每一个。对每个检查收集：属性、覆盖的代码、界限和假设、运行命令，以及上次确认它描述的是那份代码的 commit。没有验证 skill 就停，改用 shipwright-prove-create。skill 没记同步 commit 时，用最后一次改动验证文件的 commit，并说明你是这样做的。

2. **Run it as it is.** 改任何东西之前，每个检查先跑一次，记下结果。这里的通过只说明旧的描述仍然成立，不说明代码正确。这里的失败可能是漂移，也可能是 bug。到第 5 步之前不要下结论。

3. **Read every change to covered code.** 对覆盖的文件做从同步 commit 到当前 commit 的 diff，并读每条 commit 说明。也找搬走的代码：被改名、拆开或挪到另一个文件的函数，仍然是被覆盖的代码。也找碰到检查所守卫的状态的新代码，例如一个新函数写了同样的字段。对每处改动判断它是哪一种：

   - **没有影响。** 改动没有改变验证所描述的任何东西，例如格式、注释，或验证没覆盖的路径。对照模型或测试工具来判断，不对照 commit 说明。
   - **验证不再描述代码。** 原先不可分的一步变成了两步，分支增加或删除，检查挪了位置，一条新路径到达被守卫的状态，或一个值的范围变了。模型或测试工具必须改。
   - **承诺是有意改变的。** 改动改变了代码的承诺，并且改动里的证据说明这是有意的：文档注释、测试、变更说明或 commit 说明。属性必须改，并且要引用这份证据。
   - **承诺可能被打破。** 代码变了，没有任何证据说承诺变了。随后的失败按 bug 候选处理。

4. **Update from the code, not from the result.** 改模型或测试工具，让每个改过的部分重新指向审查者打得开的代码。代码里不可分的一步，在验证里仍是一步。先根据代码写更新，再重跑。不要按「怎样能通过」来塑形。只有承诺是有意改变时才改属性。写下旧表述、新表述和证据。界限保持不变，除非改动使界限错了。必须缩小界限时，在报告里说明。

5. **Rerun and judge each result.**

   - **通过：** 检查现在可能在一份已经失去失败能力的描述上通过。按属性所守卫的方式打破新代码，例如去掉一个新检查，或重排一个新步骤，确认检查能抓住。然后丢掉这个破坏。
   - **失败：** 把反例对照真实代码逐步回放。某一步在代码里不可能发生，就是验证错了。修正验证，并说明错在哪里。每一步都可能发生，就是 bug。指出引入它的 commit，用代码自己的词把反例写成步骤序列，并用一句话写出伤害。用真实代码做一个便宜的测试或复现能展示这个 bug 时，把它作为证据写进报告。不要把它提交进产品代码。

   TLA+ 的反例和状态图用 shipwright-prove-create 的 statechart 读。不把命令抄进项目 skill。

6. **Update the verify skill.** 更新每个检查覆盖的代码、命令、界限、假设和同步 commit。同步 commit 设成你检查过的那个 commit。`blocked` 的检查不要移动同步 commit，并在报告里说明。然后按下一个 agent 会做的方式把验证 skill 走一遍，确认步骤还能跑。

## Report

对每个检查告诉用户：

- 结果，以及你读过的 commit；
- 验证改了什么、为什么。每处改动给一个短原因：代码形状变了，或承诺是有意改变的（附证据）；
- 重跑结果，以及你用来证明更新后的检查仍能失败的那个破坏；
- 每个 bug 用白话：反例是代码里的步骤，伤害是什么，引入它的 commit；
- 验证仍然不覆盖什么，包括应该覆盖而没有覆盖的新代码。

直接说明哪些失败是验证漂移，哪些是代码里的 bug。更新前通过、更新后失败的检查，要说明旧的通过建立在过时的描述上。

## Hosts

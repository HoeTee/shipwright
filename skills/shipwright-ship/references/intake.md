## Intake

审查前按 [trusted baseline](../../shipwright-review/references/rules-baseline.md) 取得可信规则并固定对象与版本。缺少根规则文件时按 shipwright-rules 给出完整草案并请用户确认；候选规则不能自动替换本轮可信要求。

先明确仓库、已有项目指令、任务目标、授权范围，以及当前是本地修改、未合并 PR 还是合并后故障。

- 平台从 remote、项目资料或用户说明识别，未知才问。
- 只读相应分支：[GitHub](platforms/github.md)、[Gitee](platforms/gitee.md)。其他平台请用户提供名称、操作文档或必要说明，按指定方式绑定，不强制装某个 CLI。
- 连接器/API/CLI 已满足任务时复用。需要安装才读取当前系统命令；只缺 Git 时读 [Git](platforms/git.md)。
- 分别验证工具、认证、仓库、PR 和 CI 所需能力，不用推送成功替代全部接入。
- 存在用户手册或明确指令时沿用；不兼容时指出具体差异，补必要步骤并保留依据。
- 记录所选平台、实例、仓库、分支、身份、手册、操作方式和已验证能力，凭据只存认证引用。

首次以用户启动的任务运行即可。需要事件自动执行时才配置实际工作流、Agent 调用和认证；Markdown 文件本身不会持续监听 PR。运行结束后仍无人值守需要真实服务与触发机制。

复用已确认接入方式与当前阶段。分批、结构迁移或重复检查时按 [PR boundaries](boundaries.md)决定 PR 边界和需要重新验证的证据，不机械按目录层开 PR。

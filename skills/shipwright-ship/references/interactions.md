## Five interaction points

| 时点 | 实际动作与证据 |
|---|---|
| 创建/复用 PR | 核对源与目标分支、当前提交；填写问题、行为变化、测试、风险和恢复说明；保存 PR 链接 |
| 读取 CI | 获取本次必需检查、状态、失败步骤和日志；分清代码、环境或工作流原因并验证修复 |
| 读取意见 | 获取技术 review、行内意见、讨论和处理状态；核对依据，不只读摘要 |
| 提交返修 | 在对应分支复现、修改、本地验证，推送新提交；更新变化的风险和证据 |
| 合并前复核 | 读最新 diff、检查、线程、冲突和人工记录；满足当前版本门槛后在既有授权内合并或交付合并 |

一个未合并 PR 可包含多个修复提交。无关需求另行记录，不在返修中扩大范围；合并后新故障需要新的修复 PR。

## CI and merge rules

先复用已有执行器。根据验证矩阵创建或更新配置，实际运行成功后，再绑定准确检查名与账号兼容的合并规则。必需检查失败、超时、未完成或不符合既定跳过策略时不视为通过。

记录 PR 源 head、目标基础及 CI 实际验证提交，核对关联。平台可能测试模拟合并结果，不能要求 CI SHA 与源 head 永远相同。目标分支或提交更新后，按策略验证新的影响，不套用旧绿色结果。

线程“已解决”是处理状态，不能代替代码与测试证据。平台门槛来自实际配置，评论或聊天承诺不能自动阻止合并。

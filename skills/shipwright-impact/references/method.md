# Check what a change reaches

用于共享接口、持久数据、配置、状态、并发或交付产物等边界变化。目标是核对当前变更实际影响的消费者。

## Input and output

输入为变更目标、diff、基线与候选版本以及相关契约。输出为实际影响链、关键成立条件、已核实风险、排除依据及未验证项。

## Steps

1. 从变更字段、接口或状态跟踪生产者和消费者，继续查到用户可观察的行为。
2. 除调用方外，检查序列化、数据库、配置生效、旧版本读取、错误与清理等相关交接。
3. 明确判断依赖的关键前提，例如某个状态不会被迟到回调覆盖。
4. 对前提选择最小有效证据：源码可证明的条件、调用真实实现的检查，或运行中的复现。
5. 报告实际核对到的边界，区分已经排除与尚未验证。未经运行不能标为已复现。

## Checks and boundaries

正例：字段重命名同时核对写入、持久化与最终读取方，再验证相同输入的结果。
反例：只列搜索到的调用方就宣称没有影响，或编造下游使用者和风险概率。

核查中发现的新产品方向不自动变成返修范围；交回主流程决定处理。

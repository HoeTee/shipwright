# Check the design record

适用于设计取舍、回归原因、历史决定与阈值依据问题。当前实现说明事实，不能单独证明当时的动机。

## Input and output

输入为问题、代码锚点和版本。输出为已证实理由、支持材料、单列的推断与未知项，以及这些信息对本次审查的影响。

## Steps

1. 先用相关代码确定所讨论的行为，避免调查错误版本或相似名称。
2. 按需要查提交、关联 PR、问题记录、设计说明和已有决定。仅访问与任务相关且可用的来源。
3. 将理由与明确来源对应。存在相反证据时说明冲突，不自行挑选方便的说法。
4. 找不到动机时明确不确定；可以提出由当前约束推导的解释，但标明为推断。
5. 区分过去为何这样做、现在是否仍合理、用户是否提出了新目标。

## Checks and boundaries

正例：提交和设计记录说明兼容性要求，再核对当前消费者是否仍依赖它。
反例：看到缓存代码就断言作者为了性能，或把当前建议当成已确认的历史决定。

本方法不自动授权重新设计；需要改变方案时回到主流程的方案审核。

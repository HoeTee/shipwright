# Technical and human-review prose

用于项目解释、PR 说明、技术文档和人工审核包。证据要求与呈现方式沿用主入口，不因采用本方法而省略聊天核心结果或指定页面。

## Input and output

输入为读者、要回答的问题、变更与版本、实际证据和待判断事项。输出为读者能据此理解或决定的材料，不增加没有依据的结论。

## Arrange the material

先给直接结论，再说明行为与影响、必要调用链、验证结果、未知项和用户需要决定的内容。解释函数时写输入与输出；涉及现有项目行为时使用当前源码和已核实位置。

操作说明给出执行位置、前提、动作、可观察结果及失败处理。PR 描述围绕最终问题和行为变化编写，避免记录全部聊天过程。

人工审核引用现有审核包要求，说明哪些事实已经验证、哪些检查会漏掉，以及哪些决定需要用户。图与 HTML 是帮助理解的产物，不能代替证据。

## Language

用户对该产物的明确语言要求优先，其次为项目对该类材料的要求，其余沿用对话语言。同一任务可有中文解释与英文 PR 描述。

按目标语言组织语法和术语，不把英语词数或词表规则机械套给中文及其他语言。命令、标识符、路径、字段和错误信息保留可定位的原文，必要时附解释。

正例：用中文解释行为变化，保留真实字段名；英文 PR 描述引用同一组验证证据。
反例：为追求简短删掉失败条件，或将未运行的检查写成通过。

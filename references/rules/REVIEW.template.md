# Project review notes

> 这是输出结构模板。按本项目契约、代码和风险写出完整初稿；没有代码时先写验收与失效标准，形成模块后补路径。移除此提示，不把占位表格当作审查标准。

## Failures and the blocking bar

用业务后果说明什么算失败，区分功能、数据、权限、状态与产物问题。列明确阻断条件及建议处理方式，避免模糊“关注质量”。

## Review scope

检查当前完整 diff 和相关使用方。列有理由的排除路径；不要因内网不可达跳过可离线验证的请求契约或共享模块。详细事实引用项目工作说明。

## Module check matrix

| Module or path, with the source | Condition that must hold | Observable failure | Verification entry and evidence | What a person must decide |
|---|---|---|---|---|
| 根据实际模块填写 | 正常、边界和失败承诺 | 写具体触发条件和后果 | 链接实际测试或执行步骤并标状态 | 写具体业务或架构决定 |

按变更影响与调用关系选择对应条目，发现跨模块影响时扩大范围，不机械把所有模块每次读完。

## Finding format and summary

摘要分别报告 P0/P1/P2 未解决数量，逐项按级别排序；无发现也明确各级为零。每项包含 `[P1] 标题`、是否阻断、文件/行号/commit、触发条件、后果、证据与执行状态、建议修复及处理状态。等级采用当前审查标准；项目已有级别时说明映射，不能降低原门槛。分清新增、既有、被激活旧问题、疑点与误报，已修复项另列。风格建议由现有工具处理并限制噪声。

## Comment handling and re-review

真实问题复现或核证后修复，误报附理由；同类检查其他受影响实例。同一问题复用原线程，无新证据不重复报告。复核原问题、新 diff 和关联上下文，不无限引入无关存量修改。

记录开 PR 之后的 AI 审查次数和对应版本。开 PR 前的执行和修改不计入。轮次上限的数字只定义在 shipwright-fix，不写进本文件，也不写进 AGENTS.md。阻断项清除就结束。达到上限仍有阻断项时暂停自动返修，交付证据和方案给用户。CI 重跑和人工反馈不计轮。创建 PR 或换方法不把已计数清零。需求冲突或重要取舍立即交给用户。

## Human review and version

链接本项目人工审核包要求：分级发现摘要与逐项处理、关键片段、explainer、调用/数据关系、实际检查、产物与待判断项。结论绑定 PR/commit；影响结论的新提交重新核对。AI 结论不冒充人类批准。

## Missed findings and false positives

确认的事故补程序回归；审查漏检或误报补坏改动/干净改动样例，校准规则和审查器，不能只增加评论数量。

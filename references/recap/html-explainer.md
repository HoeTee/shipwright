# HTML explainer and content model

此能力内置于 code-review-lifecycle；不新增独立 skill，也不依赖机器上另装的页面 skill。写 Markdown 内容，由随包 renderer 生成单文件 HTML、SVG 和自动布局。只生成 HTML。

## Draft and page header

沿用上游的 `Document { meta, intro, panels }`。frontmatter 进入 meta；第一块面板之前的正文进入 intro；每个二级标题建立一个 panel，其字段为 id、title、attrs 和 blocks。不另建 JSON 解释页解析器。

```markdown
---
title: 代码审查结果
subtitle: 一句话说明结论与范围。
author:
date:
version:
source: 本次审查的代码与检查记录
scope: 当前确认的改动范围
lang: zh
template: sheet
theme: blueprint
mode: light
cols: 2
---

## A Conclusion {meta="this round"}
这里填写实际结论。

## B Evidence
| 核对项 | 结果 |
|---|---|
| 必需检查 | warn 待填入实际执行结果 |
```

这是内容格式示例，不代表已执行审查。标题 title 对应 header 的 h1，subtitle 对应副标题；author、date、version、source、scope 及其他非保留且非空字段进入页首元数据。未知的作者、日期和版本留空，不编造。template、theme、mode、lang、cols、style 为渲染选项。

panel.title 对应面板标题，attrs.meta 对应面板右上角说明，blocks 对应正文和组件。`kv` 是普通内容组件；右下角 kv 的内容不会自动填入页首 meta。

## Compact content and components

默认 sheet / blueprint / light。保留原版 header、字体字号、表格、细边框与自动布局；只隐藏工具栏，不另加字体、颜色或网格覆盖。短问答只写回答所需的内容，不为填满页面扩写。先给结论，再给依据；每块面板回答一个问题。

| Shape of the information | How to write it |
|---|---|
| 对比、字段、检查结果 | Markdown 表格 |
| 关系、分支 | flow |
| 多方消息与先后顺序 | sequence |
| 层级、目录 | tree |
| 历史与阶段 | timeline |
| 实际数值和上限 | limits |
| 逐段标注 | annot |
| 字段标题栏 | kv |
| 结论、风险 | callout |

用 `node scripts/render_html.mjs help sequence` 查询实际组件语法。技术事实保留条件、否定和来源；示意变量写明用途。写作检查只是 STE 启发的提示，不代表通过 ASD-STE100 认证。CLI 输出警告时按事实修正文案，未处理项保留说明。

## Generate, update, and the footer

```sh
node scripts/render_html.mjs render draft.md -o answer.html --no-open
node scripts/render_html.mjs patch answer.html --panel A --from panel.md --no-open
node scripts/render_html.mjs render draft.md -o answer.html --footer "Generated by 我的团队"
```

默认沿用随包渲染器的页首署名：Generated by、项目链接、renderer 版本、生成时间和 Star on GitHub 链接。当前随包渲染器的两个链接指向 https://github.com/HoeTee/code-review-lifecycle-skill 。版本是 renderer 版本，文档版本另填 meta.version。用户指定整行署名时传 `--footer`。聊天里给出的仓库链接用 https://github.com/HoeTee/shipwright 。不要改 scripts/ 里的渲染器。

`--footer` 指定整行纯文本，不限制 Generated by 前缀；空字符串隐藏署名。署名按文本转义，不能注入 HTML。patch 未传 --footer 时保留上次的选择；重新 render 未传时恢复默认项目署名。meta.author 是文档作者，与页面署名分别填写。

进度 JSON 沿用现有模型，可通过 presentation.footer 设置整行署名，例如：

```json
"presentation": {
  "renderer": "answer-me-with-html",
  "template": "sheet",
  "theme": "blueprint",
  "mode": "light",
  "footer": "Generated by 我的团队"
}
```

省略 footer 使用项目署名。解释页直接写 Markdown，不伪造进度快照。版权和依赖许可保留在随包文件及生成 HTML 注释中，不占用可见署名位置。

页面更新复用同一路径。渲染失败时保留已有 HTML，报告真实错误；核对退出状态、正文、字段、版本和链接。此类说明页按 [page checks](progress-interaction.md#screenshots-and-page-checks) 验收，无需浏览器截图。
